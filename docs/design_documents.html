    Key Database Design Principles:

    1. Multi-Modal Payment Architecture (`sales`):

  • `payment_method` accommodates `Cash`, `GCash`, `Card`, and `Split`.
  • Dedicated `cash_amount` and `gcash_amount` columns capture the exact dual-tender breakdown for split payments, ensuring accounting audits reconcile cash drawer balance and GCash wallet deposits.

    • 2. Immutable Inventory Ledger (`inventory_transactions`):

  • Protected against direct `UPDATE` and `DELETE` via MySQL database triggers (`trg_block_inventory_transactions_update`, `trg_block_inventory_transactions_delete`).
  • Protected against table truncation through foreign-key child table `inventory_transactions_lock`.
  • Guaranteed signed movement validation via SQL `CHECK` constraint: sales/losses require `quantity_change < 0`, receipts/additions require `quantity_change > 0`.

    • 3. Dual-Layer Compatibility Matrix:

  • Exact-Fit Compatibility: Maps direct parts to exact motorcycle unit models (`product_compatibilities` & `motorcycle_models`).
  • Platform-Level Compatibility: Groups families of models sharing identical engine/chassis platforms (e.g. Yamaha Aerox Platform, Honda Click Platform) via `compatibility_groups` and `product_compatibility_groups`.

    • 4. Serialized Asset Control:

  • Distinct individual units (e.g., ECUs, Batteries, Expensive Electronics) are tracked through `product_serials` and bound to sales invoices via `sale_item_serials` to protect against duplicate allocation or fraudulent warranty claims.

    • 5. Security & Cryptographic Isolation:

  • `users.password` uses bcrypt (10 salt rounds) with live strength enforcement.
  • `users.token_version` is incremented on password changes to immediately revoke all existing JWTs across active browser sessions.
  • `password_otps` stores SHA-256 code hashes with a 10-minute expiry and a 5-attempt brute-force threshold.

    4. Architectural Quality Attributes & Defense Readiness

    Quality AttributeArchitectural ImplementationVerification Method
    Multi-Tender FlexibilitySplit Payment engine allows splitting bills across Cash and GCash with live balance tracking, change calculation, and database tracking of `cash_amount` and `gcash_amount`.Verified on POS checkout with automated invariant testing: `cash + gcash >= total`.
    Data IntegrityDatabase-level triggers prevent ledger modification; `SELECT ... FOR UPDATE` row locking prevents concurrent double-spend of serial numbers.Trigger rejection unit tests & concurrent checkout test scenarios.
    Authentication & AccessJWT authentication with dual-role RBAC (`admin` vs. `staff`). Immediate multi-device invalidation through `users.token_version`. Live password checklist enforces strong credentials.Automated OTP test suite & password strength validation.
    Email ResilienceOutbound OTP emails use the Resend HTTPS REST API over port 443, eliminating SMTP timeout blocks (`ETIMEDOUT`) enforced by cloud hosting firewalls.Live delivery verification to Gmail in 1.2s.
    Fault Tolerance & Zero DowntimeAuto-migration scripts ([`backend/utils/ensureSchema.js`](file:///c:/Inventory/backend/utils/ensureSchema.js) & schema patches) add missing tables and columns on server boot without manual SQL execution.Automated deployment boot verification.
    Navigation & ErgonomicsStrict `end` route matching on sidebar navigation prevents multi-link active states (e.g. Sales Reports vs Discrepancy Audit). Fitment Search and Compatibility Rules consolidated into Account & Security (`/profile`).UI visual audit on Desktop & Mobile viewports.
    Cart Preservation & Void Re-openPOS payment modal supports closing via `Esc` key, background backdrop click, or "← Back to Cart" button without losing cart items. Completed sales can be immediately reversed via "↩ Void & Return to Cart" on the receipt modal, restoring stock and repopulating cart.Interactive modal state lifecycle verification & database stock recovery test.
